# Actual natural-language-selected object editing

This supersedes **manual selection only** figures. It does not relabel those
images as language-selected results. A new experiment directory keeps the
complete external-LLM input, raw response, parsed operation/opaque IDs, and
native output generated by executing those exact IDs.

1. Use original frozen 1.5B Object8 / Register32 checkpoint's cached image-only
   AR descriptions. Replay these same captions to extract PGOT owner bundles.
2. Independently pretrained Qwen3-VL-4B-Instruct acts as a **text-only external
   controller**. It receives the request and all parsed thing-owner generated
   descriptions for A/B, shuffled with opaque IDs. No image, predicted/GT
   coordinates, masks, reference slot IDs, expected answers, or GT descriptions.
3. The controller chooses `operation`, `target_id`, `donor_id`. No lexical
   fallback, re-prompting, manual correction, or reference-ID substitution.
4. Execute exactly those IDs. Removal drops the selected owner and rewrites
   Writer memories with that owner's predicted winning patches excluded.
   Replacement substitutes only selected donor visual memory, keeping source
   semantic state and other owners/registers unchanged.
5. Original Reader -> DiT -> RAE decoder produces reconstruction and edit from
   the same initial noise. FP32, seed1234, guidance1, ten steps. Finite/identity
   and raw-completion-to-execution audits run afterwards.

```bash
cd /home/jovyan/PGOT
GPU=1 bash scripts/run_language_object_editing.sh
```

`GPU=1 LIMIT=1` is the end-to-end first-case smoke. Remove LIMIT to resume
the exact same manifest and process all eight requests. A new request file or
code/model/settings change requires a fresh OUTPUT_DIR; existing manual figures
and training processes are never modified.

The first six requests are the user's cup/dog, bench/board, giraffe/refrigerator
figure examples. Two controls follow: nonexistent airplane removal (should
abstain), and dog removal in the SAME bench image (tests actual selection of a
different owner). Source images remain qualitative curated examples, not an
unbiased referring-expression benchmark. All failures/abstentions remain saved.

Output `outputs/language_object_editing_gpu1`:

- `manifest.json`: fixed requests/caption provenance/full candidate-ID mapping.
- `plans/edit_*.json`: exact messages/rendered text/raw completion/selected IDs.
- `selector_info.json`: distinct controller snapshot/runtime/settings.
- `owners/<image_id>`: fresh replayed representations and predicted ownership.
- `edits/edit_*`: source/donor, predicted selected region, reconstruction,
  actual native edit, and execution metadata (or explicit non-generation).
- `protocol.json`, `validation.json`, `logs/`: restore/runtime/audit evidence.
- `figure/object_editing_language_selected.png` / PDF / SVG: fresh six-case
  3x2 figure assembled only after the full exact-selection audit.
- `selection_report.md`, `review_all_requests.jpg`: every request and actual
  controller decision, including the two controls and any non-generations.

Claims: **external LLM selects MLLM-generated, language-linked object
representations for composition; PGOT generates from manipulated representations**.
Not: PGOT itself directly follows arbitrary editing instructions; independent
selector accuracy; perfect preservation or exact donor identity. These selected
visual-memory replacements mainly demonstrate object appearance transfer.

## Completed GPU1 run

The actual end-to-end LIMIT=1 smoke passed. The full run then resumed that
case and completed all eight controller decisions: seven native edits generated,
and the nonexistent-airplane request explicitly abstained with NO fallback image.
Both bench and dog requests on image261161 selected different opaque owners;
the generated dog-removal result leaves the bench visible. This is a control
demonstration, not a selector accuracy/success-rate benchmark.

All eight raw-completion-to-execution decisions passed audit; zero manual
corrections. Model restore audit: zero missing/unexpected unique parameters,
all four schema markers registered, Object8 / Register32 x4 confirmed. Focused
tests including legacy transfer/gallery/selection plus new planner/renderer:
63 passed. All eight results were visually inspected; the six-case Figure was
assembled from the newly generated images, not the earlier manual edit outputs.

Qualitative observations: cup/bench/giraffe disappear; black-white dog receives
donor-like brown coat; board receives yellow markings; refrigerator receives
steel-like appearance. Background preservation, anatomy and exact donor identity
are imperfect. The controller is an independent text-only model, and PGOT
remains the representation extractor and native image generator, not a directly
instruction-tuned editor.
